스위치 자산 기록에는 워크스테이션이 VLAN 20에 속한다고 나옵니다. 그런데 센서가 저장한 패킷에는 태그가 없습니다. 스위치가 전달에 사용한 구간, 관측한 링크에 실린 태그, 수집기에 저장된 바이트를 각각 확인하면 이런 차이를 설명할 수 있습니다.

## 1. 포트 문맥과 함께 태그 읽기

**VLAN**은 데이터 링크 계층에서 논리적으로 나눈 전달 구간입니다. 스위치는 유입 포트 설정과 프레임의 태그를 바탕으로 해당 구간을 결정합니다. **액세스 포트**는 흔히 단말 쪽 링크에서 하나의 데이터 VLAN을 태그 없이 전달합니다. **트렁크**는 보통 여러 VLAN을 함께 전달하며 태그로 구간을 구분합니다. 설정에 따라 트렁크에서도 한 VLAN이 태그 없이 오갈 수 있습니다. **PVID**는 포트에서 수신 프레임을 분류할 때 쓰는 VLAN 식별자입니다. 태그 없이 들어와 수신이 허용된 프레임이 한 예입니다. 공급자마다 용어와 송수신 정책이 다를 수 있으므로 링크 양쪽 설정을 확인하세요.

802.1Q 태그는 Ethernet 출발지 MAC과 그다음 유형·길이 필드 사이에 4바이트를 삽입합니다. 앞쪽 2바이트는 태그 프로토콜 식별자(**TPID**), 뒤쪽 2바이트는 태그 제어 정보(**TCI**)입니다. TCI는 네트워크 바이트 순서로 읽습니다. 상위 3비트는 우선순위(PCP), 다음 1비트는 폐기 적격 표시(DEI), 하위 12비트는 VLAN 식별자(VID)입니다. `0x8100`은 일반적인 C-태그, `0x88a8`은 S-태그를 나타냅니다. 태그가 하나 늘 때마다 다음 유형 필드의 위치가 4바이트씩 밀립니다. 사업자망에서 흔히 쓰는 태그 스택에서는 바깥 서비스 태그, 안쪽 고객 태그 순으로 읽습니다. 익숙한 번호가 나와도 태그의 순서를 함께 남기세요.

| 캡처 증거 | 확인할 수 있는 사실 | 다음에 확인할 사항 |
| --- | --- | --- |
| 보이는 태그 헤더 없음 | 저장된 프레임에 태그가 보이지 않음 | 원본 포트, 미러링, 드라이버 및 캡처 위치 |
| C-태그 VID 20 | 저장된 프레임의 해당 층에 VID 20이 있음 | 번호가 의미 있는 사이트, 스위치와 정책 |
| VID 0, PCP 5 | 태그에 우선순위가 있으며 특정 VLAN은 지정하지 않음 | 포트 설정과 수신 분류 |
| 바깥 VID 200, 안쪽 VID 20 | 그 순서로 태그 두 개가 있음 | 이 링크에서 각 번호가 나타내는 구간 |
| 헤더 도중 캡처가 끝남 | 레코드의 바이트만으로 디코딩하기 어려움 | 저장 길이·원본 길이, snaplen, 다른 관측 |

## 2. 정상 요청 한 건 따라가기

가상 환경의 09:10 UTC에 워크스테이션이 `198.51.100.20` 쪽으로 프레임을 보냅니다. 단말 쪽 액세스 링크에서는 태그가 없습니다. 스위치는 수신 포트 설정에 따라 VLAN 20으로 분류합니다. 업링크에서는 VLAN 20을 태그로 전달하므로 스위치가 송신 시 C-태그를 붙입니다. 이 업링크의 TAP은 복사 경로에서 태그가 유지되면 이를 관측할 수 있습니다. 같은 업링크를 복제하는 로컬 SPAN은 태그를 제거한 사본을 내보낼 수도 있습니다. 예를 들어 아래에 인용한 Catalyst 9300 버전에서는 로컬 SPAN의 기본 출력에 태그가 없으며, 설정에 따라 원본 캡슐화를 보존할 수 있습니다. 다른 장비에 그대로 적용하기 전에 실제 플랫폼과 세션을 확인하세요.

09:10:01에 같은 센서에서 주소·포트가 같은 두 번째 프레임이 보이지만 VID는 30입니다. 구간별 주소 범위가 겹치면 동일한 네트워크 튜플도 정상적으로 반복됩니다. 센서와 구간을 포함해 시각, 전체 프레임이나 확보한 상위 계층 트랜잭션 정보로 대조하세요. 3계층 경계 앞뒤를 비교할 때는 라우팅 또는 주소 변환도 따로 확인합니다. VID는 해당 링크의 문맥을 보여 주며 전역 흐름 ID로 사용하기 어렵습니다.

## 3. 설정 변화와 수집 공백 조사하기

1. **토폴로지와 관측 위치를 기록합니다.** 사이트, 스위치·포트, 액세스·트렁크 역할, PVID 또는 네이티브 VLAN, 허용 VLAN, 시각, 미러링의 원본·목적지와 방향을 적으세요. 센서에서는 인터페이스, 링크 계층 유형, 수집기 버전, 저장 길이 제한(snaplen), 필터, 드롭 카운터와 원본 파일을 보존합니다. 물리 링크, 논리 VLAN 인터페이스, 정규화된 사본 중 어디에서 캡처했는지 적으세요. NIC, 드라이버, 캡처 스택에 따라 태그가 바이트에서 제거되거나 다시 붙을 수 있습니다. 논리 VLAN 인터페이스에서 받은 센서는 헤더가 없어도 구간을 메타데이터로 남길 수 있습니다.
2. **독립 관측과 대조합니다.** 예상 구간마다 승인된 엔드포인트 사이에서 식별할 수 있는 정상 테스트 메시지를 사용하세요. 해당 구간의 TAP 또는 동작을 확인한 미러링을 센서 캡처 및 디코딩 로그와 비교합니다. 태그 변화가 있었다면 프레임 자체가 없는 경우와 일부 헤더만 빠진 경우를 구분해 기록하세요. Wireshark에서는 패킷 상세와 원시 바이트를 살펴봅니다. `vlan.id == 20`, `ieee8021ad.id == 200` 같은 표시 필터는 특정 디섹터 필드를 조회합니다. 다중 태그는 프로토콜 트리와 설치 버전을 함께 확인하세요. 캡처 필터가 제외한 프레임은 표시 필터로 되살릴 수 없습니다. libpcap 문법에서 `vlan` 한정자가 나올 때마다 뒤쪽 디코딩 오프셋이 4바이트씩 밀립니다. 태그 없음·단일·다중 캡처로 필터를 검증한 뒤 수집에 적용하세요.
3. **구성 문제와 오용 가능성을 구분합니다.** 잘못된 트렁크 허용 목록, 태그 없는 VLAN 처리 불일치, 정상적인 서비스 태깅, 승인되지 않은 변경 때문에 예상 밖 구간이 보일 수 있습니다. 낯선 태그를 봤다는 사실만으로 실제 전달을 입증할 수 없습니다. 포트 구성 변경 이력, VLAN별 MAC 학습, 허용된 VLAN 간 흐름과 방화벽 로그를 검토하세요. 설정의 적용 시각과 다른 구간에서 실제로 프레임을 받았는지 확인합니다.
4. **승인 범위에서 탐지와 복구를 검증합니다.** 사이트, 인터페이스, 방향과 안팎 태그의 역할을 포함해 예상 밖 구간 조합을 집계하세요. 태그가 없거나 구간을 매핑할 수 없으면 명시적으로 남깁니다. 검증된 자산 목록과 달라진 항목을 탐지하고 승인된 예외를 대조합니다. 조치 후에는 승인된 실습 구간에서 무해한 앱 통신으로 허용 경로와 정책상 차단 경로를 각각 시험합니다. 실제 전달, 로그와 센서 카운터를 비교하세요. 캡처가 정상이어도 구간 분리 정책은 따로 입증해야 합니다.

## 4. 오프라인 실습 · 가상 캡처 두 개

<a href="{{ '/assets/labs/vlan-capture-lab.py' | relative_url }}" download="vlan-capture-lab.py">Python 가상 캡처 실습 다운로드</a>

빈 작업 폴더에서 Python 3으로 실행하세요. 스크립트는 새 `vlan-lab` 폴더에 작은 Ethernet PCAP 두 개를 만들고 자체 예제를 디코딩합니다. 문서용 IP, 실습용 로컬 관리 MAC과 고정된 페이로드 표식을 사용합니다. 패킷을 전송하지 않으며 파일에는 Ethernet 프레임 검사 시퀀스(FCS)가 없습니다. 센서 사본은 관측 차이를 예시하며 특정 스위치나 NIC를 모의 실행하지 않습니다.

~~~bash
python3 vlan-capture-lab.py
~~~

| 표식 | 링크에서 본 형태 | 센서 사본 |
| --- | --- | --- |
| A | 태그 없음 | 태그 없음 |
| B | C-태그 VID 20 | 같은 메시지에 태그가 보이지 않음 |
| C | C-태그 VID 30 | C-태그 VID 30, B와 동일한 IP 튜플 |
| D | 바깥 S-태그 200, 안쪽 C-태그 20 | 안쪽 C-태그 20만 남음 |
| E | 우선순위 태그 VID 0, PCP 5 | 같은 우선순위 태그 |
| F | 완전한 C-태그 VID 40 | 6번 프레임은 15바이트만 저장돼 TCI를 읽을 수 없음 |

`PASS`가 여섯 줄 나와야 합니다. Wireshark가 설치돼 있다면 생성된 파일을 오프라인에서 엽니다. 완전한 프레임은 가상 페이로드의 표식을 대조하세요. 6번 프레임의 저장 바이트에는 표식이 없으므로 프레임 번호와 길이 필드를 비교합니다. Ethernet 프로토콜 트리를 읽은 뒤 위 표시 필터를 적용해 보세요. 폴더가 이미 있어서 실행이 멈추면 새 작업 폴더에서 다시 실행합니다. 뷰어에서 열리지 않으면 Ethernet PCAP을 지원하는지, 파일이 온전히 전달됐는지 확인하세요. Python 파일 생성과 디코딩은 클라우드에서 실행했고 Wireshark 필터는 공식 필드 문서로 검토했습니다.

## 5. 확인 문제와 완료 기준

1. **센서 사본에 VLAN 태그가 없으면 네이티브 VLAN으로 전달됐나요?** 사본에서 태그를 볼 수 없다는 사실을 확인했습니다. 구간을 정하기 전에 원본 포트, 미러링 캡슐화와 캡처 경로를 확인하세요.
2. **B와 C는 튜플이 같으니 같은 흐름인가요?** 실습에서는 서로 다른 태그 구간에서 튜플을 재사용했습니다. 구간 식별 정보를 포함하고 메시지 표식을 대조하세요.
3. **VID 0은 VLAN 번호가 0이라는 뜻인가요?** 특정 VLAN을 지정하지 않는 우선순위 태그입니다. 포트 설정에서 분류를 확인하세요.
4. **짧은 PCAP 프레임으로 원래 프레임이 비정상이었음을 입증할 수 있나요?** 저장 길이와 원본 길이를 비교합니다. 잘린 레코드만으로는 원래 바이트를 모두 확인할 수 없습니다.

여섯 사례를 재현하고, 링크와 센서에서 각각 무엇을 봤는지, 태그 순서나 부재, 다음에 확인할 구성 또는 동작을 기록하면 완료입니다.
