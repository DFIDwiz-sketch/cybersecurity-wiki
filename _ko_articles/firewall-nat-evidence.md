**학습 목표.** 방화벽이 내린 결정과 센서가 본 패킷을 구분하고, NAT 전후에 주소나 포트가 바뀐 동일 통신을 찾습니다. 1–3절에서 개념을 익히고 6절의 가상 기록을 직접 연결해 보세요.

## 1. 방화벽과 NAT는 각각 무슨 일을 하나요?

방화벽은 어느 구간의 어떤 통신을 허용할지 정책을 적용합니다. **상태 기반 방화벽**은 기존 흐름을 추적해 돌아오는 패킷이 그 흐름에 속하는지도 판단할 수 있습니다. NAT(Network Address Translation)는 패킷의 주소를 바꿉니다. 주소와 전송 계층 포트를 함께 바꾸는 경우 NAPT 또는 일반적으로 PAT라고 부릅니다. 한 장비가 방화벽과 NAT를 모두 수행할 수 있습니다.

| 용어 | 하는 일 | 조사할 값 |
| --- | --- | --- |
| 5튜플 | 한 방향의 통신을 주소·포트·프로토콜로 표현 | 출발지와 목적지 IP·포트, TCP/UDP |
| SNAT | 출발지 주소를 변경하고 구성에 따라 포트도 변경 | 원래 출발지와 변환된 출발지 |
| DNAT | 목적지 주소를 변경하고 구성에 따라 포트도 변경 | 외부 서비스 주소와 실제 서버 주소 |
| 정책 결정 | 해당 장비가 통신을 허용하거나 차단 | 장비·정책·영역·시각·결과 |
| 관측 지점 | 센서가 패킷을 볼 수 있는 위치 | NAT 전후 구간, 인터페이스, 양방향 가시성 |

TLS나 앱 로그인 결과는 별도 계층의 증거입니다. NAT 구성이나 방화벽 허용 기록만으로 이를 판단하지 마세요.

## 2. 정상 SNAT와 DNAT를 따라가기

![내부 관측 · NAT 전 → 192.0.2.10:51400 → 경계 방화벽 · 출발지 변환 → 외부 관측 · NAT 후 → 198.51.100.10:40001 → 서버 · 203.0.113.20:443]({{ '/assets/diagrams/nat-evidence-ko.svg' | relative_url }})

가상 내부 호스트 **192.0.2.10:51400**이 서버 **203.0.113.20:443**에 TCP로 연결합니다. 경계 방화벽은 지정 정책에 따라 허용하고 출발지를 **198.51.100.10:40001**로 바꿉니다. 내부 센서는 원래 주소를, 외부 센서는 변환된 주소를 봅니다. 정상 응답이 돌아오면 변환 장비가 저장한 매핑을 바탕으로 그 응답을 내부 호스트로 전달합니다.

반대로 외부 클라이언트가 **198.51.100.20:8443**을 찾는데 경계 장비가 요청을 **192.0.2.80:443**으로 보낼 수도 있습니다. 이 경우 내부 센서에서 목적지가 달라집니다. 정책이 원래 주소·변환 주소 중 어느 것을 평가하는지와 기록 형식은 장비와 배치에 따라 다릅니다. 위 순서를 특정 제품의 처리 순서로 가정하지 말고 장비 설정과 맞춰 보세요.

모든 IP는 문서용 주소입니다. 실제 조사에서는 터널·프록시가 있는지도 확인하세요. 프록시는 별도 연결을 만들 수 있어 NAT 전후 5튜플 비교만으로는 요청을 연결하기 어렵습니다.

## 3. 방화벽, Zeek, 패킷은 서로 다른 증거를 줍니다

| 출처 | 기록할 내용 | 확인할 한계 |
| --- | --- | --- |
| 방화벽 트래픽 로그 | 장비·가상 시스템, 영역, 정책, 허용·차단, 원래·변환 주소 및 포트, 시작·끝 시각 | 시작·종료 로그 설정과 필드 버전 확인 |
| Zeek conn.log | 센서·uid, id.orig_h/p, id.resp_h/p, proto, ts, duration, conn_state | 센서가 본 구간의 연결 상태. 정책·사용자 신원은 다른 자료에서 확인 |
| 패킷 캡처 | 시간, 인터페이스, 방향, TCP 플래그와 실제 응답 | 손실·비대칭 경로·보존 기간·암호화 영향 |
| 앱·호스트 로그 | 실제 프로세스, 사용자, 요청 ID, 인증·처리 결과 | 시계·프록시·필드 범위를 대조해야 다른 계층과 연결 가능 |

PAN-OS 트래픽 로그는 원래 주소와 NAT 주소·포트, 세션 ID, 정책, 종료 사유 등의 필드를 제공하는 예입니다. 수집기가 구분된 열을 보존하는지 먼저 확인하세요. 세션 ID는 장비나 가상 시스템 등의 범위를 붙여 사용합니다. Zeek uid는 해당 관측 내에서의 연계에 쓰고 다른 제품의 세션 ID와 동일한 값으로 취급하지 않습니다.

예를 들어 방화벽에 allow가 있고 외부 Zeek에 **TCP S0**가 있다면 정책 허용과 센서에서 응답을 보지 못한 연결 시도를 각각 기록하세요. 대상 호스트의 수신 여부, 반환 경로, 센서 손실을 추가 확인합니다. **TCP SF**는 Zeek가 정상 연결 성립과 종료를 관측했다는 단서입니다. HTTP 성공이나 사용자의 의도를 따로 조사하세요.

## 4. 같은 통신을 연결하는 순서

1. 관측 위치를 먼저 적습니다. NAT 전에 캡처했다면 원래 주소를, NAT 뒤라면 변환된 주소를 비교합니다. 흐름 방향은 첫 패킷 또는 장비의 원문 필드로 정규화하세요.
2. UTC 기준 시각, 측정한 시계 오차, 연결 시작·끝과 로그 수신 시각을 구분합니다. 긴 세션은 종료될 때까지 종료 로그가 없을 수 있습니다.
3. 장비 경계·테넌트, 프로토콜, 두 끝점의 IP와 포트, 겹치는 시간대로 후보를 좁힙니다. 포트는 시간이 지나면 재사용될 수 있습니다. 동일한 공용 IP만으로 원래 내부 호스트를 지정하지 마세요.
4. 후보가 여러 개면 자료의 방향·시각·장비와 중복 수집을 확인합니다. 연결 근거가 모자라면 미연결 또는 모호로 남겨 둡니다.
5. 정책 결과와 실제 흐름을 구분해 보고합니다. 접근 성공이나 유출을 조사할 때는 서버·앱·호스트 증거를 추가합니다.

실제 장비 간 시계가 다르면 먼저 정상 시험으로 오차를 측정하고, 그에 근거한 시간 허용 범위를 문서화하세요. 이 실습의 시각은 이미 정렬된 것으로 가정합니다.

## 5. 이상 통신을 조사하고 방어를 검증하기

| 관측 | 가능한 정상 설명 | 추가 확인 |
| --- | --- | --- |
| 차단 기록이 갑자기 늘어남 | 앱 재시도, 장애 후 복구, 승인된 진단 | 변경 일정, 대상 수, 기준선과 후속 허용 |
| 익숙하지 않은 내부 호스트의 외부 연결 | 승인된 업데이트나 새 배치 | NAT 매핑, 호스트 프로세스, 목적지와 시각 |
| 외부의 관리 서비스 접근 관측 | 승인된 운영 작업 또는 과한 노출 | 실제 DNAT 대상, 승인 출발지, 인증 결과 |
| 허용됐으나 응답 없음 | 반환 경로 문제나 센서에 한 방향만 보임 | 대상 로그, 양방향 PCAP, 센서 상태 |

방어 검증은 자가 소유·승인 환경에서 정상 HTTP 요청 한 건을 보내 내부·외부 관측과 허용 정책 로그에 모두 기록되는지 확인하는 것부터 시작합니다. 미리 준비된 차단 정책과 별도 시험용 서비스가 있으면 정해진 주소·포트에 대한 한 건의 요청으로 차단 로그를 확인하세요. 운영 정책의 변경이나 임의 대상 스캔이 필요 없습니다. 차단이나 격리를 결정할 때는 번역된 공용 주소를 공유하는 정상 호스트의 영향도 확인합니다.

## 6. 오프라인 실습 · 가상 로그 12건

[nat-correlation.csv]({{ '/assets/labs/nat-correlation.csv' | relative_url }}) · [nat-correlation.py]({{ '/assets/labs/nat-correlation.py' | relative_url }})

두 파일을 같은 폴더에 저장하고 Python 3으로 실행하세요. CSV는 제품의 원본 로그가 아니라 NAT 이후 관측을 정규화한 교육 자료입니다. `inside`의 obs-04는 외부 요청이 DNAT된 **뒤**의 내부 관측입니다. 센서의 상태는 미리 부여된 예시이며 실제 패킷 파서를 실행하지 않습니다.

~~~bash
python3 nat-correlation.py
~~~

| 사례 | 기대 결과 |
| --- | --- |
| obs-01 / obs-02 | 같은 외부 주소·포트·목적지지만 시간 차이로 fw-01과 fw-02를 구분 |
| obs-03 | fw-04에 연결. 방화벽 허용과 센서의 TCP S0를 함께 기록 |
| obs-04 | fw-05와 연결. 외부 8443이 내부 443으로 변환 |
| obs-05 / obs-06 / obs-07 | 각각 프로토콜·장비 경계·시간 차이로 미연결 |
| fw-03 | 지정 경계에서 차단. 동일 통신의 다른 경로는 별도 조사 |

마지막 줄에 `PASS: four correlations, three unlinked observations, one firewall deny`가 표시됩니다. 파일을 못 찾으면 이름과 폴더를 확인하세요. 결과가 다르면 방향, NAT 열, 경계, UTC 구간을 비교하세요. 분석기는 이 자료에 맞춘 예이며 운영의 비대칭 경로·재수집·시계 오차까지 자동 처리하지 않습니다. 게시 과정에서는 CSV 분석을 실행 검증했습니다. 실제 방화벽, Zeek와 패킷 수집은 별도 시험이 필요합니다.

## 7. 확인 문제와 완료 기준

- **같은 공용 IP가 찍혔으면 같은 호스트인가요?** 변환된 포트·프로토콜·목적지·시각·장비 범위를 대조합니다.
- **방화벽 허용이면 서버가 요청을 처리했나요?** 방화벽의 정책 결정을 관측했습니다. 센서와 서버 로그로 이후를 확인합니다.
- **이 예에서 내부 센서가 192.0.2.80:443을 본 이유는요?** 외부 8443으로 보낸 요청이 DNAT된 뒤의 경로를 관측했습니다.

기록 두 건의 NAT 전후 5튜플을 그려 보고, 미연결 세 건에서 어떤 필드가 달랐는지 설명하세요. 마지막으로 fw-04의 허용과 obs-03의 S0를 서로 다른 관측으로 한 문장에 적으면 완료입니다.
