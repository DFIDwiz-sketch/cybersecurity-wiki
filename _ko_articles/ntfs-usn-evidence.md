보고서가 다른 폴더에 새 이름으로 나타났습니다. 어떤 파일이 바뀌었는지, 누가 옮겼는지, 서버 밖으로 전송됐는지는 각각 다른 질문입니다. NTFS 변경 저널로 파일과 이름 변경의 단서를 찾고, 수행자와 전송 여부는 별도 증거로 확인할 수 있습니다.

## 1. 변경 저널 한 줄이 알려 주는 것

**NTFS**는 Windows 파일 시스템입니다. **볼륨**은 파일 시스템을 담을 수 있는 논리적 저장 단위입니다. NTFS는 볼륨별 변경 저널을 유지할 수 있어 검색 인덱서 같은 도구가 이전에 읽은 위치부터 변경 사항을 확인할 수 있습니다. **USN**(업데이트 시퀀스 번호)은 저널 스트림의 위치입니다. 레코드마다 길이가 다르고 수집 필터도 적용될 수 있으므로 USN 숫자 사이의 차이를 누락된 이벤트 수나 시간 간격으로 계산하면 안 됩니다.

| 필드 또는 맥락 | 의미 | 조사에서 쓰는 법 |
| --- | --- | --- |
| 호스트와 볼륨 식별 정보 | 어느 파일 시스템에서 수집했는지 | 원본 볼륨 또는 스냅샷과 수집 출처를 기록합니다. 드라이브 문자는 달라질 수 있습니다. |
| `UsnJournalID` | 상태 조회에서 얻은 저널 인스턴스 ID | 다음 읽기 위치와 함께 저장합니다. ID가 달라지면 연속성을 다시 확인합니다. |
| `FileReferenceNumber` | 볼륨 안에서 변경 대상 객체를 가리키는 참조값 | 참조값 전체와 버전을 남깁니다. 공식 문서에 나온 NTFS MFT 참조 구조에서는 시퀀스 부분을 버리면 같은 슬롯을 재사용한 객체를 혼동할 수 있습니다. |
| `ParentFileReferenceNumber`, `FileName` | 이름을 담는 레코드에서 상위 폴더의 참조값과 객체 이름 | 사건 당시의 디렉터리 자료로 경로를 재구성합니다. 지금 경로는 당시와 다를 수 있습니다. |
| `Usn`, `TimeStamp`, `Reason` | 스트림 위치, 제공될 경우 레코드 시각, 변경 이유 비트 | 같은 저널 인스턴스의 순서는 USN으로 읽습니다. 다른 자료와는 UTC로 대조하고 원래 값을 보존합니다. |
| V2·V3의 `SecurityId` | 해당 파일이나 폴더에 연결된 보안 식별 값 | 객체에 관한 필드입니다. 작업을 요청한 계정이나 프로세스는 감사 기록으로 확인합니다. |

이 학습 장에서는 이름이 들어 있는 V2 형태의 내보낸 자료를 사용합니다. V3는 더 넓은 파일 참조값을 사용합니다. 범위 추적의 V4는 구조가 다르고 V2와 같은 이름·시각 필드가 없습니다. 수집할 때 레코드 버전과 길이를 함께 남기세요. 스프레드시트나 JavaScript에서 큰 참조값과 USN이 반올림되지 않도록 문자열이나 정확한 정수 형식을 사용합니다.

## 2. 합쳐진 변경 플래그와 이름 변경 따라가기

하나의 변경 이유 필드에 여러 플래그가 들어갈 수 있습니다. 예를 들어 `0x80000003`에는 `DATA_OVERWRITE`(1), `DATA_EXTEND`(2), `CLOSE`(0x80000000)가 설정돼 있습니다. 해당 객체에서 이 종류의 변화가 기록됐다는 뜻입니다. 같은 종류의 작업이 반복돼도 플래그 하나로 남을 수 있습니다. 플래그마다 쓰기 한 번을 뜻하지 않으며 쓰기 순서와 내용도 알 수 없습니다. `BASIC_INFO_CHANGE`는 시각이나 파일 특성 변경에서도 생깁니다. 어느 속성이 바뀌었는지는 다른 자료로 확인하세요.

같은 볼륨 안에서 이름을 바꾸거나 옮기면 이전 이름과 새 이름의 기록이 생길 수 있습니다. 실습의 `R01`에는 상위 폴더 `0x0001000000000018` 아래 `draft.csv`와 변경 이유 `0x1000`(이전 이름)이 있습니다. 뒤의 `R02`에는 상위 폴더 `0x0002000000000021` 아래 `report.csv`와 `0x2000`(새 이름)이 있습니다. 두 행은 전체 파일 참조값, 볼륨, 저널 인스턴스가 같습니다. 이 실습 자료의 범위에서는 `R01`이 가장 유력한 이전 이름 후보입니다. 상위 폴더가 달라지면 이름뿐 아니라 폴더도 옮겼는지 확인하세요. 두 행 사이에 다른 파일의 기록이 들어갈 수 있습니다.

이름이나 시각만 비슷한 행은 주의해서 읽습니다. `R03`은 다른 볼륨, `R04`는 다른 저널 인스턴스입니다. `R05`는 파일 이름과 참조값의 낮은 자릿수가 같지만 전체 참조값은 다릅니다. `R09`처럼 이전 이름 후보가 둘이라면 두 후보를 남기세요. 다른 볼륨으로 복사한 뒤 원본을 삭제한 경우에는 출발지와 목적지 양쪽의 증거가 필요합니다.

## 3. 조사에 필요한 기록이 남았는지 확인하기

**커서**는 수집기가 다음에 읽을 곳으로 저장한 위치입니다. 원본 호스트와 볼륨을 먼저 확인한 뒤 저널 ID를 비교합니다. 현재 상태 조회는 한 시점의 결과이므로 조회 시각과 실제 읽기 결과를 함께 남기세요. 여기서는 이전에 저장한 다음 읽기 위치를 0이 아닌 16진수 값으로 표현합니다.

| 관측 | 해석 | 다음 확인 |
| --- | --- | --- |
| 같은 ID, 커서가 `FirstUsn`·`LowestValidUsn` 이상이며 `NextUsn` 미만 | 조회 당시 범위 안에 있습니다. | 실제 읽기 결과, 변경 이유 필터, 파서가 지원하는 형식을 확인합니다. |
| 커서가 `FirstUsn` 미만 | 저장한 위치가 현재 읽을 수 있는 첫 위치보다 이전입니다. | 오래된 내보내기 자료나 스냅샷을 찾습니다. 보존 공간을 위해 오래된 기록이 잘렸을 수 있습니다. |
| 커서가 `LowestValidUsn` 미만 | 현재 저널 인스턴스의 유효 하한보다 앞섭니다. | 인스턴스 이력과 읽기 결과를 확인합니다. 파일 열거 결과에는 더 오래된 USN이 나타날 수 있습니다. |
| 저널 ID가 달라짐 | 저장한 위치만으로 현재 인스턴스와의 연속성을 입증할 수 없습니다. | 두 ID를 보존하고 이전 자료를 찾습니다. 현재 인스턴스의 기준점은 별도로 정합니다. |
| 커서가 `NextUsn`과 같음 | 상태를 조회했을 때의 끝 위치입니다. | 조회 이후에 새 활동이 기록될 수 있습니다. |
| 커서가 `NextUsn`보다 큼 | 현재 조회한 스냅샷의 끝과 저장 위치가 맞지 않습니다. | 볼륨 또는 스냅샷 혼동, 오래된 목록, 진수 변환 오류를 확인합니다. |

범위 안인데도 이름 변경 기록 한쪽이 없다면 시간 필터, 변경 이유 필터, 수집 시작·끝 경계, 지원하지 않는 레코드 형식을 살펴보세요. 새 저널 ID에도 정상적인 원인이 있을 수 있습니다. 공백만으로 기록 변조를 단정하지 않습니다.

## 4. 다른 증거와 함께 수집하고 조사하기

승인된 Windows 호스트의 관리자 권한 셸에서 NTFS 볼륨의 저널 상태를 조회할 수 있습니다. `C:`를 확인한 로컬 볼륨으로 바꾸세요. 아래 명령은 상태와 범위를 읽습니다. 출력 원문과 오류를 보존하세요. 오프라인 실습에는 Windows가 필요하지 않습니다.

```cmd
fsutil usn queryjournal C:
```

1. **수집 상황을 보존합니다.** UTC 수집 시각, Windows 빌드, 볼륨, 저널 ID, 범위, 마지막으로 읽은 위치와 수집 설정을 적습니다. 원본 수집 자료나 승인된 볼륨 스냅샷을 보존하고 검증된 사본으로 조사하세요. 파서 버전과 필터, 오류도 남깁니다. 접근할 수 없거나 저널이 활성 상태가 아닌 경우는 정상적으로 조회한 뒤 결과가 없었던 경우와 다릅니다.
2. **파일과 경로를 재구성합니다.** 원본 볼륨과 저널 인스턴스로 나눈 뒤 전체 파일 참조값을 맞춥니다. 이전·이후 상위 폴더 참조값, 경로 자료, 사건 시각에 해당하는 마스터 파일 테이블(MFT) 자료를 비교합니다. 수행한 프로세스는 단말의 파일 이벤트에서 찾으세요. 나중 시점의 자료로 재구성한 경로는 당시 스냅샷이나 디렉터리 기록이 없다면 가설로 남깁니다.
3. **다른 가능성을 점검합니다.** 서로 무관한 사용자 폴더에서 이름 변경·쓰기·삭제가 급증하면 조사할 단서입니다. 정상 동기화, 백업, 배포, 앱 저장 동작과 비교해 변경 속도, 영향을 받은 경로, 사용자·호스트 역할을 살핍니다. 가장 이른 변경의 파일을 찾아 실제 프로세스나 세션과 연결하세요. 확장자나 플래그 하나로 암호화, 반출, 공격자를 확정하지 않습니다.
4. **판단에 맞는 증거로 대응합니다.** SMB 공유 조사에서는 서버에서 수집한 Security 파일 감사 기록이 있는지 확인합니다. 이벤트 4663에는 관련 감사 정책과 객체의 접근을 감사하도록 지정한 SACL이 필요합니다. 접근 권한 사용과 전송 완료의 차이는 [SMB 파일 감사 학습 장]({{ '/ko/wiki/smb-file-audit-evidence/' | relative_url }})에서 확인하세요. 내용 변경은 정상 버전, 해시 또는 앱 기록과 비교합니다. 악성 활동을 뒷받침하는 독립 증거가 있다면 보존하고 사고 대응 절차에 따라 격리·복구를 조율합니다. 확인하지 못한 점도 남깁니다.

## 5. 오프라인 실습 · 열 가지 확인

[가상 사례 및 기록 JSON]({{ '/assets/labs/ntfs-usn-cases.json' | relative_url }})과 [Python 확인 스크립트]({{ '/assets/labs/ntfs-usn-review.py' | relative_url }})를 같은 폴더에 저장하세요. JSON은 원본 NTFS 기록을 읽기 쉽게 나타낸 가상 자료입니다. 볼륨과 저널 라벨도 실습용입니다. Python 3만으로 확인할 수 있습니다. 실제 볼륨을 조사한다면 별도 승인과 승인된 사본을 사용하세요.

1. `K01`부터 `K06`까지 먼저 저널 ID를 비교하고 16진수 범위를 확인합니다. 각 결과에서 무엇까지 판단할 수 있는지도 적으세요.
2. `R02`, `R05`, `R09`의 이전 이름 후보를 찾습니다. 같은 볼륨, 인스턴스, 전체 파일 참조값을 사용하고 실습에 제공된 범위에서 찾으세요. `R06`의 이유 비트는 따로 읽어 봅니다.
3. 다음 명령을 실행하세요. 마지막 줄은 `10 synthetic checks passed.`입니다.

```bash
python3 ntfs-usn-review.py
```

| 사례 | 기대 결과 |
| --- | --- |
| `K01`, `K06` | 각각 조회 당시의 범위 안과 끝 위치입니다. |
| `K02`, `K03` | 각각 현재 읽을 수 있는 위치보다 앞서 있거나, 저널 인스턴스가 바뀌었습니다. |
| `K04`, `K05` | 각각 조회 당시의 끝보다 뒤에 있거나, 현재 인스턴스의 유효 하한보다 앞에 있습니다. |
| `R02`, `R05`, `R09` | 각각 후보 하나(`R01`), 후보 없음, 후보 둘(`R07`, `R08`)입니다. |
| `R06` | 덮어쓰기, 길이 증가, 닫힘 비트가 있습니다. 횟수와 순서는 알 수 없습니다. |

파일을 찾지 못하면 두 파일 이름과 저장 위치를 확인하세요. `R05`를 `R01`과 묶었다면 참조값을 중간에서 잘라 읽지 않았는지 점검하세요. `R09`에 가장 가까운 행만 선택했다면 다른 후보도 남깁니다. 실습용 후보 비교는 고정 자료에 맞췄습니다. 운영 파서에서는 레코드 버전, 시간 범위와 겹치는 변경 이벤트를 처리해야 합니다.

**검증 범위.** Python으로 가상 검사 10개를 실행했습니다. Windows 조회 명령과 레코드 구조는 Microsoft 공식 문서에서 확인했습니다. 실제 Windows 볼륨 저널 조회는 이번 검증 범위에 포함되지 않았습니다.

## 6. 확인 문제와 해설

1. **USN으로 몇 번 쓰기가 있었는지 알 수 있나요?** USN은 스트림 위치입니다. 여러 쓰기가 같은 비트 하나로 남을 수 있습니다.
2. **이름과 파일 참조값의 낮은 자릿수가 같으면 같은 객체인가요?** 전체 참조값, 볼륨, 저널 인스턴스를 확인하세요. 실습의 `R05`는 참조값 위쪽의 시퀀스가 다릅니다.
3. **같은 저널 ID라도 커서가 `FirstUsn`보다 작다면 그 시각에 변화가 없었다고 해도 되나요?** 그 위치는 현재 저널에서 읽을 수 없습니다. 다른 보존 자료를 찾으세요.
4. **행에 `SecurityId`가 있습니다. 누가 옮겼나요?** 객체에 관한 필드입니다. 대상과 시각을 실제 수행 계정에 연결하는 감사 로그나 단말 자료를 찾아야 합니다.

**완료 기준.** 커서 사례 여섯 건을 설명하고, 이전 이름이 모호한 사례에 모든 후보를 남기세요. 확인한 변경 한 가지, 사용 가능한 수집 범위, 수행자 확인에 필요한 다음 증거를 짧은 조사 메모로 적습니다.
