**학습 목표.** 네트워크 경보를 근거로 승인된 호스트 증거 수집을 요청합니다. 수집이 끝났는데 일치하는 결과가 없는 경우, 요청이 진행 중인 경우, 필요한 원본이 수집 범위에 없었던 경우, SIEM 전달이 확인되지 않은 경우를 구분합니다.

## 1. 요청할 때만 수집한다는 것은 무슨 뜻인가요?

**Velociraptor**는 엔드포인트의 상태나 남아 있는 기록을 조사하는 도구입니다. **클라이언트**는 장치에 등록된 에이전트입니다. 서버의 **조직(Organization)**은 관리와 데이터의 범위를 나눕니다. **클라이언트 ID**는 에이전트 등록을 식별하므로, 요청 전에 실제 자산과 대응하는지 확인합니다. **아티팩트**는 Velociraptor Query Language(VQL)로 작성된 수집 작업 정의입니다. 읽는 원본과 매개변수, 실행 조건을 포함할 수 있습니다. **플로(Flow)**는 수집 작업 한 건이며 고유 ID가 있습니다. 결과에는 구조화된 **행**이나 별도로 **업로드된 파일**이 담길 수 있습니다. 기대 결과는 아티팩트마다 다릅니다.

| 방식 | 먼저 던질 질문 | 증거 범위의 한계 |
| --- | --- | --- |
| 단일 클라이언트 수집 | 승인된 특정 호스트에 어떤 기록이 남아 있나요? | 요청 시 실행합니다. 호스트와 아티팩트가 해당 이력을 제공해야 과거를 확인할 수 있습니다. |
| 헌트(Hunt) | 같은 조사 질문을 승인된 여러 장치에서 확인해야 하나요? | 대상마다 별도의 수집을 예약합니다. 라벨과 만료 시간은 참여 범위에 영향을 줍니다. 전체 대상 수와 개별 플로를 함께 봅니다. |
| 클라이언트 모니터링 | 앞으로 이 유형의 이벤트를 계속 수집해야 하나요? | 미리 설정한 클라이언트 이벤트 쿼리를 실행합니다. 오프라인일 때는 설정과 한도에 따라 임시 저장되고 재접속 뒤 도착할 수 있습니다. 사건 발생 시점에 수집 범위에 포함돼야 합니다. |

호스트 한 대가 확인됐다면 그 장치에서 범위를 좁혀 시작합니다. 헌트가 예약됐거나 중지됐다는 사실로 각 장치의 실행 결과를 알 수는 없습니다. 대상 조건, 체크인, 각 플로와 사유를 확인합니다. 오늘의 스냅샷은 현재 상태의 증거입니다. 어제의 사건을 조사하려면 과거 기록을 읽는 아티팩트와 해당 시각을 포함하는 보존 이력이 필요합니다.

## 2. 정상 조사 한 건을 따라가 보세요

![네트워크 단서에서 호스트 후보를 검증합니다. 수집 범위를 정하고 서버에서 실행 상태·원본·결과를 확인한 뒤, 보존과 SIEM 도착을 각각 점검합니다.]({{ '/assets/diagrams/endpoint-collection-flow-ko.svg' | relative_url }})

가상 훈련망의 센서가 10:02 UTC에 외부로 향하는 연결을 경보로 기록했습니다. 주소 할당 기록으로 장치 후보를 좁히고, 자산 목록에서 작업용 시험 장치에 등록된 클라이언트 ID를 확인합니다. 분석가는 사건 시각의 주소 할당과 자산 범위를 대조합니다. 조사 질문은 **10:00–10:05 UTC의 기존 호스트 로그에 해당 연결과 프로세스가 함께 남아 있는가**입니다. 현재 열린 소켓 목록으로는 다른 시점의 질문에 답하게 됩니다.

1. **네트워크 단서를 보존합니다.** 센서 이름과 관측 지점, 원본 시각·시간대, 출발지·목적지 주소와 포트, 경보나 연결 식별자를 기록합니다. 필요하면 NAT와 DHCP 범위를 확인합니다. 경보나 IP 하나만으로 호스트나 사용자를 확정하지 않습니다.
2. **수집 요청 범위를 정합니다.** 승인된 조직·클라이언트 ID, 읽을 원본과 UTC 구간을 사건 기록에 적습니다. 설치된 아티팩트 정의에서 운영체제 조건, 예상 채널과 원본, 시간대, 필터, 행·파일 한도, 권한과 수집 영향을 확인합니다. 필요한 가장 작은 범위를 고르고 매개변수와 사용자 정의 버전을 남깁니다.
3. **수집 서버에서 실행을 확인합니다.** 플로 ID와 상태를 기록합니다. **Logs**의 쿼리 메시지, 올바른 결과 집합의 행, 파일이 필요한 경우 **Uploaded Files**의 실제 전송 기록을 확인합니다. 요청을 보냈거나 클라이언트가 체크인했다고 해서 수집이 끝난 것은 아닙니다. 원본을 읽을 수 있었는지, 요청 시각이 보존 범위에 들었는지, 시간 초과나 수집 제한이 있었는지 봅니다.
4. **증거를 대조하고 전달을 확인합니다.** 반환된 행의 시각, 원격 주소·포트, 프로세스가 네트워크 단서와 일치하면 해당 연결 가설을 뒷받침합니다. 시각과 대상 범위를 확인하고 정상 업무 문맥도 확인합니다. 원본을 접근 제한된 위치에 저장하고 출처 식별자와 필요시 체크섬을 기록합니다. SIEM으로 전달하는 환경이라면 예상 인덱스와 시간 범위에 도착했는지 수집 성공과 별도로 확인합니다.

네트워크 기록만 계속 수집하고 엔드포인트는 요청할 때 수집하는 환경이라면, 수집 요청 시각, 플로 완료 시각, 원본 이벤트 시각, SIEM 수신 시각을 구분해 남기세요. Splunk에서 경보 발생 시각만 검색하면 수집 시각을 기준으로 들어온 결과를 놓칠 수 있습니다. 데이터의 시간 필드 매핑을 확인하고 서버 내보내기와 목적지에서 같은 원본 행 식별자를 대조합니다. 전달 과정에서 필드 이름이 바뀌면 매핑을 확인한 뒤 조직·클라이언트·플로를 검색합니다.

가상 사례의 결과는 서명이 확인된 업데이트 프로세스와 예정된 작업으로 설명됩니다. 보고에는 이 설명의 근거를 남깁니다. 호스트 결과가 없으면 로그가 꺼져 있었거나, 보존 기간이 지났거나, 해당 로그가 연결 이벤트를 수집하지 않았을 수도 있습니다. 해당 출처에서 무엇을 확인할 수 있었는지 좁혀 정리합니다. 한 출처가 비어 있다는 이유로 사건을 종결하지 않습니다.

## 3. 결과 0건을 어떻게 보고하나요?

| 관측값 | 보고할 수 있는 사실 | 이어서 확인할 내용 |
| --- | --- | --- |
| 대기 또는 실행 중 | 수집이 끝난 결과를 아직 확인할 수 없음 | 마지막 체크인, 범위와 조사 기한 |
| 완료, 결과 0건, 원본·시각 포함 확인 | 그 출처와 시간 구간에서 쿼리에 일치하는 행이 없었음 | 필터가 의도와 맞는지 보고 정확한 쿼리와 범위 근거를 보존 |
| 완료, 원본 건너뜀 또는 보존 공백 | 관련 원본이나 구간에 대한 판단을 보류 | 실행 조건, 활성 채널, 보존 및 다른 출처 |
| 일부 행은 도착했으나 시간 초과 또는 제한 | 일부 증거만 확보 | 도착 자료를 보존하고 더 짧은 승인 구간이나 다른 출처를 확인 |
| 행은 있으나 필요한 첨부 파일이 없음 | 구조화 결과는 왔으나 파일 수집 요건을 충족하지 못함 | 아티팩트 동작, 업로드 로그와 한도 |
| 서버에는 행이 있으나 SIEM에서 보이지 않음 | 수집은 확인했고 SIEM 전달은 미확인 | 전달기·라우팅, 인덱스 권한, 파싱, 발생 시간과 수신 시간 |

**오용 가능성과 방어 확인.** 엔드포인트 수집은 민감한 기록을 읽을 수 있고 에이전트에 높은 권한이 부여된 환경도 있습니다. 승인되지 않은 대량 요청, 변경된 아티팩트, 잘못 적용한 그룹 라벨은 자료 노출과 장치 부하로 이어질 수 있습니다. 수집 역할과 승인 범위를 제한하고 아티팩트 정의를 검토하세요. 민감한 요청은 서버 감사나 변경 기록과 대조합니다. 공급자는 감사 대상 작업을 확인할 출처로 `Server.Audit.Logs`를 문서화합니다. 실제 가시성과 보존 여부를 확인하고 수집량·라벨 대상의 갑작스러운 변화를 비교하세요. 느린 플로 한 건은 정상 부하로도 설명할 수 있습니다. 승인되지 않은 수집임이 확인되면 사고 대응 절차로 요청을 중지하고, 감사·플로 증거와 영향받은 장치 및 후속 사본을 확인합니다.

## 4. 오프라인 실습 · 가상 수집 기록 9건

[가상 사례 자료]({{ '/assets/labs/endpoint-collection-cases.json' | relative_url }})와 [Python 검토기]({{ '/assets/labs/endpoint-collection-review.py' | relative_url }})를 같은 폴더에 저장한 뒤 Python 3로 실행합니다.

```sh
python3 endpoint-collection-review.py
```

각 사례의 `expected`는 요청 조건이고 `observed`는 검토한 관측값입니다. 상태 이름과 `coverage`는 가상으로 정규화한 필드입니다. 실제 제품의 API 필드로 사용하면 안 됩니다. 실제 조사에서는 상태를 보고 범위를 추정하지 말고 범위를 확인한 근거를 기록하세요. 모든 식별자·시각·행 개수는 가상이며, 검토기는 서비스나 네트워크에 연결하지 않습니다.

| 사례 | 기대 판정 | 이유 |
| --- | --- | --- |
| C01 | 결과 확보 | 범위와 출처가 확인되고 2행이 있음 |
| C02 | 범위 확인, 결과 0건 | 범위와 출처가 맞지만 쿼리에 일치하는 행이 없음 |
| C03 | 대기 | 큐에 있고 최종 수집 결과는 없음 |
| C04 | 수집 범위 공백 | 실행 조건을 충족하지 않아 필요한 원본을 건너뜀 |
| C05 | 수집 미완료 | 한 행이 도착한 뒤 시간 초과 |
| C06 | 첨부 누락 | 행은 있지만 필요한 파일 한 개가 없음 |
| C07 | 범위 불일치 | 클라이언트·플로 표기는 같지만 조직이 다름 |
| C08 | 전달 미확인 | 서버에는 2행이 있으나 SIEM 도착 근거가 없음 |
| C09 | 수집 범위 공백 | 사건 시간대의 기록이 보존 범위에 남아 있지 않음 |

**기대 결과는 사례 9건, 판정 유형 8개**입니다. 파일 오류가 나면 이름과 폴더를 확인합니다. 데이터 오류는 출력된 사례 ID의 요청과 관측 필드를 대조합니다. 0건 판정이 예상과 다르면 자료에서 대상 원본과 시각 범위를 검증했다고 표시했는지 확인하세요. 실제 사례에는 여러 문제가 함께 있을 수 있습니다. 이 실습은 먼저 어긋난 지점을 알려 줍니다.

### 승인된 환경에서 선택 확인

이미 등록된 승인된 시험 장치 한 대에서 **Collected Artifacts → New Collection**으로 이동합니다. 실행 전에 설치된 `Generic.Client.Info` 정의를 읽습니다. 공급자 기본 정의는 호스트 이름, 운영체제, 인터페이스 같은 시스템 정보를 수집하며 서버의 클라이언트 정보 색인에 반영될 수 있습니다. 시험 조직과 클라이언트 ID, 승인된 권한이 맞는지 확인한 뒤 수집하고, 플로 상태·**Logs**·시스템 정보 결과 집합을 확인합니다. 호스트 이름과 OS를 알려진 시험 자산과 대조하세요. 이 실습으로 수집 경로를 확인할 수 있습니다. 과거 연결 기록과 SIEM 전달을 검증하려면 별도 시험이 필요합니다. 수집이 시작되지 않으면 체크인과 권한을, 행이 보이지 않으면 선택한 결과 원본과 OS 적용 조건을 확인합니다. 실제 장치 식별자는 공개 보고서에 올리지 않습니다.

가상 자료 검토기는 클라우드에서 실행했습니다. 실제 제품 절차는 공급자 문서로 검토했으며 Velociraptor 배포 환경에서 실행하지 않았습니다.

## 5. 확인 문제와 완료 기준

1. **헌트에 대상이 보이지만 결과가 없습니다. 이상이 없다고 결론 내릴 수 있나요?** 대상 조건, 활성 기간 중 체크인, 플로 결과를 확인하세요. 결과가 없다는 사실은 우선 수집 범위의 문제입니다.
2. **C02와 C04에서 결과가 모두 0건인 이유는 어떻게 다른가요?** C02는 원본과 시간 범위를 확인했습니다. C04는 필요한 원본이 실행되지 않았습니다.
3. **서버에 행이 있으면 SOC가 바로 검색할 수 있나요?** C08처럼 전달 경로와 목적지 수신을 따로 확인합니다.
4. **어제 연결을 조사하는 데 오늘의 소켓 목록이 충분한가요?** 어제의 기록을 남기고 보존한 출처가 있어야 합니다.

C02·C05·C08을 구분하고 각 결론을 뒷받침한 출처를 설명하세요. 조직, 클라이언트, 플로, 아티팩트, 시간 범위, 수집 범위 및 추가 대조가 필요한 점을 짧게 남기면 완료입니다.
