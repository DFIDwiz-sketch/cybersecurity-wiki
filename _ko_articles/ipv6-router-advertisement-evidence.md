**학습 목표.** 단말이 낯선 IPv6 다음 홉을 사용하기 시작했다고 가정합니다. 링크에서 본 광고와 단말이 실제로 적용한 설정을 대조하고, 정상 이중화·설정 오류·오용 가능성을 판단하는 데 필요한 증거를 고릅니다.

## 1. IPv6 단말은 어디서 설정을 얻나요?

IPv6에서 **링크**는 노드들이 네트워크 계층에서 직접 패킷을 주고받을 수 있는 구간입니다. `fe80::/10`에 속하는 **링크 로컬 주소**는 해당 링크 안에서만 의미가 있습니다. 다른 인터페이스에서 같은 주소가 보일 수 있으므로, 경로를 기록할 때는 주소와 함께 인터페이스 또는 VLAN을 남깁니다.

**이웃 탐색(Neighbor Discovery, ND)**은 ICMPv6 메시지의 모음입니다. 단말은 라우터 요청(RS, 유형 133)을 보내 라우터 광고(RA, 유형 134)를 요청할 수 있습니다. 라우터는 주기적으로도 광고합니다. 이웃 요청과 광고(유형 135·136)는 링크 계층 주소 확인과 도달 가능성 점검 등 다른 역할을 합니다. 중복 주소 탐지(DAD)는 링크에서 주소를 이미 사용 중인지 확인합니다. **SLAAC**는 주소를 자동으로 구성하는 방식입니다. 단말은 광고된 접두사와 스스로 만든 식별자를 합쳐 주소를 구성할 수 있습니다.

| 단말의 설정 | RA에서 볼 곳 | 의미 |
| --- | --- | --- |
| 기본 라우터 | 발신 주소와 Router Lifetime | 0보다 크면 기본 라우터 후보. 0이면 해당 기본 라우터 사용 철회 |
| 링크에서 직접 닿는 접두사 | 접두사 정보 옵션(PIO)의 L 플래그 | 접두사를 링크 안으로 취급할지 판단. 주소 생성은 별도 |
| SLAAC 주소 | PIO의 A 플래그, 접두사, 선호·유효 수명 | 조건에 맞는 접두사로 주소 구성. 새 연결에 덜 선호되는 주소도 유효 기간 동안 쓸 수 있음 |
| 재귀 DNS 서버 | RDNSS 옵션과 수명 | DNS 서버 주소를 알림. 수명 0은 이 방식으로 알린 주소의 사용 철회 |
| DHCPv6 정보 | M·O 플래그와 단말 정책 | 관리형 주소나 기타 설정 제공 여부를 알림. SLAAC와 같이 쓸 수 있고 기본 라우터 광고는 별도 기능 |

Router Lifetime은 기본 라우터에 적용됩니다. PIO와 RDNSS에는 별도 수명이 있어서 Router Lifetime이 0이어도 다른 옵션이 유효할 수 있습니다. 각 필드를 따로 확인하세요. DHCPv6 표준은 2026년 1월 RFC 9915가 RFC 8415를 대체했습니다.

## 2. 정상 광고 하나를 따라가세요

가상의 VLAN 40에서 새 단말이 RS를 보냅니다. 라우터 R1이 `fe80::1`에서 응답합니다. IPv6 **패킷 헤더**의 Hop Limit은 255, Router Lifetime은 1,800초입니다. `2001:db8:40::/64` 접두사에는 L과 A가 설정돼 있고, PIO의 선호 수명은 30분, 유효 수명은 60분입니다. RDNSS는 `2001:db8:40::53`을 1,200초 동안 광고합니다. 단말은 정책에 따라 R1을 다음 홉으로 등록하고 DAD 뒤 주소를 구성하며, 광고된 DNS를 사용할 수 있습니다.

![같은 링크에서 단말의 라우터 요청과 라우터 광고가 오갑니다. 단말이 광고를 적용했는지는 경로·주소·DNS 상태를 보고 확인합니다.]({{ '/assets/diagrams/ipv6-ra-ko.svg' | relative_url }})

**Hop Limit은 두 곳에 나옵니다.** IPv6 패킷 헤더의 Hop Limit은 RA를 검증하는 데 씁니다. RA 내부의 Cur Hop Limit은 단말이 앞으로 보낼 패킷에 권고하는 기본값입니다. 내부 값이 0이면 그 설정을 지정하지 않습니다. RFC 4861의 검증에는 링크 로컬 발신 주소, 바깥 Hop Limit 255, ICMPv6 코드 0, 유효한 체크섬 등 여러 조건이 있습니다. 이 조건을 통과해도 승인된 라우터라는 증거는 별도로 필요합니다. NIC가 체크섬을 계산하기 전의 캡처나 일부만 저장된 캡처에서는 체크섬을 정확히 판단하기 어려울 수 있습니다.

## 3. 예상 밖 광고와 실제 영향을 구분하세요

같은 링크에 승인되지 않은 장치가 설정을 광고하면, 이를 받아들이는 단말에서 트래픽 경로가 바뀌거나 통신이 끊기거나 DNS가 달라질 수 있습니다. 실수로 켠 라우터 기능이나 브리지로 연결된 가상 실습실도 비슷한 현상을 만듭니다. 계획된 장애 조치에서는 보조 라우터가 광고를 시작하거나 기본 라우터 한 대가 사용 철회를 알릴 수 있습니다. 미러에서 예상 밖 RA가 보였어도 보호된 포트를 통과했는지, 단말이 적용했는지는 따로 알아봐야 합니다.

| 관측한 근거 | 말할 수 있는 범위 | 추가로 확인할 자료 |
| --- | --- | --- |
| 확인된 단말 포트에서 예상 밖 RA 유입 | 발신자나 유입 지점이 승인 기준과 다름 | 스위치 포트·VLAN, 차단 여부, 단말 설정 |
| 승인된 라우터의 Router Lifetime 0 | 해당 라우터가 기본 사용 철회를 광고함 | 유지보수 기록, 이후 경로 표, 다른 옵션의 수명 |
| 승인 포트에서 접두사나 RDNSS 변경 | 광고한 설정이 기준과 다름 | 라우터 설정 이력, 이중화 장비 비교, 단말 상태 |
| 단말의 경로 또는 DNS 변경 | 단말에 실제 설정 변화가 있었음 | 적용 정책과 일치하는 RA, DHCPv6나 정적 설정 증거 |

## 4. 블루팀 수집·탐지·대응

1. **관측 범위를 고정합니다.** UTC 시각, 캡처 인터페이스와 방향, VLAN, 스위치와 포트 출처를 기록하세요. SPAN 목적지는 캡처 지점입니다. 발신 장치가 연결된 물리 포트를 알려면 별도 매핑이 필요합니다. 스위치나 하이퍼바이저가 VLAN 태그를 제거했다면 독립 자료로 VLAN을 확인하세요. 원본 패킷 기록과 관련 장비 로그를 보존합니다.
2. **링크마다 승인 기준과 비교합니다.** 이중화 장비까지 포함한 승인 라우터의 주소·MAC 조합과 유입 포트, 접두사·플래그·수명, DNS 주소·수명을 기록합니다. 링크 로컬 주소나 MAC 하나만으로 발신자를 인증할 수는 없습니다. 포트 이동, 유지보수와 VLAN 배정 변경도 확인하세요.
3. **패킷과 단말 기록을 대조합니다.** 승인된 IPv6/ICMPv6 캡처를 Wireshark로 열고 표시 필터 `icmpv6.type == 134`를 적용합니다. IPv6 헤더, RA의 Router Lifetime과 옵션을 읽으세요. 단말 담당자에게 시각과 인터페이스가 포함된 경로·주소·DNS 상태를 요청합니다. 영향을 받은 단말과 정상 단말을 비교하고 경로와 DNS 변경을 각각 확인하세요.
4. **보호 기능의 결과를 확인합니다.** 올바른 VLAN과 포트에서 RA-Guard 정책이 적용됐는지, 지원되는 경우 카운터에 어떤 결과가 남았는지 확인합니다. RFC 7113의 구현 지침과 사용 중인 플랫폼·펌웨어 문서를 대조하세요. 관련 증거를 먼저 보존하고 발신 장치가 승인되지 않았음을 확인하면 담당자와 승인 절차에 따라 해당 포트나 워크로드를 제한합니다. 이후 IPv6 경로와 DNS가 정상인지 확인하세요. ICMPv6 전체를 차단하면 정상 동작도 중단될 수 있습니다.

마지막 줄은 `Expected results: 10/10`입니다. 값이 다르면 파일을 수정하지 않고 저장했는지 확인하고 `ipv6HopLimit`, 발신 주소와 포트 조합, 두 수명을 비교하세요. 스크립트는 표준 형식으로 정리된 주소 문자열과 단순한 실습 정책을 전제로 합니다. 실제 분석에서는 IPv6와 패킷 유효성을 검사하고, 관측 범위와 여러 옵션의 변경을 함께 기록해야 합니다. 승인된 자체 환경에서는 자신이 설정한 라우터의 광고를 수신하는 위치에서 캡처해 알려진 구성과 단말 상태를 대조할 수 있습니다. 운영 링크 변경은 필요하지 않습니다. JavaScript 분류 로직을 실행했고, 장비 동작과 RA-Guard, Wireshark 필터는 공개 문서로 검토했습니다.

## 6. 확인 문제와 완료 기준

- **Router Lifetime이 0인데 DNS 서버를 알려줄 수 있나요?** 가능합니다. RDNSS의 주소와 수명을 따로 확인하세요.
- **두 VLAN에서 `fe80::1`이 보이면 같은 라우터인가요?** 두 관측에서 각각 링크와 스위치 포트의 관계를 확인해야 합니다.
- **Hop Limit 255면 승인된 라우터인가요?** 수신 패킷의 형식 검사입니다. 승인 여부는 독립적인 정책·유입 증거로 확인하세요.
- **센서가 예상 밖 RA를 봤다면 단말의 경로도 바뀌었나요?** 같은 시간대의 단말 경로를 확보해 광고 및 차단 기록과 비교하세요.

**완료 기준.** LAB-03과 LAB-08에서 관측 범위와 실제 영향을 입증할 다음 자료를 각각 적습니다. LAB-05와 LAB-09가 서로 다른 설정을 철회한다는 점도 설명하세요.
